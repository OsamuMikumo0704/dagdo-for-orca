# dagdo 使い方ガイド

[全OS共通の日本語セットアップ](README.ja.md) | [English](../README.md)

Windows・macOS・Linux 共通で `bun run start`（起動）、`bun run backup`（バックアップ）、`bun run check`（検証）が使えます。共通の起動はターミナルで動作し、Ctrl+C または Shut down で終了します。以下の PowerShell とショートカットの説明は Windows のバックグラウンド運用向けです。


dagdo は、タスク同士の「先に終わらせる必要がある」という関係を管理するアプリです。
たとえば「設計 → 実装 → テスト」とつなぐと、今着手できるタスクが分かります。
普段はブラウザで操作し、必要に応じて PowerShell からも同じデータを操作できます。
画面やコマンドの表示は英語ですが、タスク名・メモには日本語を使えます。

## 1. 起動する・終了する

以下のコマンドは **Windows標準のWindows PowerShell 5.1、またはPowerShell 7**で実行できます。PowerShell 7の追加インストールは不要です。
最初にアプリのディレクトリへ移動します。

```powershell
Set-Location 'C:\path\to\dagdo\app'
```

起動すると、バックアップを作成してからブラウザが開きます。

```powershell
.\scripts\start.ps1
```

画面のURLは **http://localhost:3737** です。ブラウザを閉じた場合も、このURLで開き直せます。
サーバーはバックグラウンドで動くため、ブラウザを閉じるだけでは停止しません。

終了するときは画面右上の「Shut down」を押し、確認画面で承認します。終了後はブラウザのタブを閉じてください。同じアプリを開いている他のタブも終了状態になります。再開には起動用ショートカットを使います。停止用ショートカットは不要になりました。

サーバーが予期せず止まると、開いているタブに操作をブロックするポップアップが表示されます。起動用ショートカットで再開すると、自動で再接続します。

保守作業では次のコマンドも使えます。

```powershell
.\scripts\stop.ps1
```

ブラウザを開かずに起動する場合は `.\scripts\start.ps1 -NoOpen` を使います。
ポート3737が別のアプリに使われている場合は、起動時にエラーになります。

### 初回セットアップが必要な場合

すでに動いている環境なら、毎回この操作を行う必要はありません。
Bun for Windows を用意したうえで、Windows PowerShell 5.1 または PowerShell 7 から次を実行します。
起動用スクリプトは Bun を `$env:USERPROFILE\.bun\bin\bun.exe` から実行します。

```powershell
bun install --frozen-lockfile
.\scripts\check.ps1
.\scripts\start.ps1
```

実行ポリシーでスクリプトがブロックされる場合は、たとえば `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1` のように実行します。この指定は起動したプロセスだけに適用され、ユーザーやPC全体のポリシーは変更しません。

## 2. ブラウザでタスクを管理する

基本の流れは「タスクを作る → 必要な順序をつなぐ → 着手できるものを進める → 完了にする」です。

| やりたいこと | 操作 |
| --- | --- |
| タスクを追加する | `New task` ボタンを使う。または、キャンバスの空白部分を `Alt` を押しながらクリックする。 |
| 一覧のタスクをマップで見る | 左一覧のタスクをシングルクリックする。 |
| タスクの詳細を編集する | タスクをダブルクリックし、中央の詳細画面でタイトル・進捗・メモなどを編集する。 |
| タイトルを変更する | タスクをダブルクリックし、詳細画面のタイトル欄を編集する。 |
| 完了にする | タスクの詳細パネルにある完了操作を使う。 |
| 依存関係を作る | 先に終えるタスクの出力ハンドルから、後に行うタスクの入力ハンドルへドラッグする。 |
| タスクや線を削除する | 対象を選択して `Delete` または `Backspace` キーを押す。 |
| 画面を移動する | `Space` キーを押しながらドラッグする。 |
| 詳細パネルを閉じる | `Esc` キーを押す。 |
| 表示を整理する | タブ、フォーカスパネル、レイアウトやテーマの切り替えを使う。 |
| 完了済みタスクを隠す | `Hide completed tasks` を使う。 |

ハンドルの位置はレイアウトによって変わります。
依存関係は「Aを完了してからBに着手する」なら **A → B** の向きです。
循環する関係（A → B → A など）は作成できません。

進捗は Ready（黄・初期値）、In Progress（緑）の2段階です。未完了の前提があるタスクは自動でBlocked（着手待ち・グレー）になります。完了済みもグレーですが、タイトルに取り消し線が付きます。進捗の変更と完了操作は詳細画面で行います。着手待ちになっても進捗は保持されます。

左一覧の境界をドラッグすると幅を140〜400pxに変更できます。右下のボタンでミニマップを開閉できます。
詳細画面の「Created on」は作成日時です。Orca連携済みのタスクにはOrcaのロゴが表示されます。
メモは作業内容や完了条件の記録に使えます。メモの上限は2,000文字相当です。
タスクの変更は保存され、CLIからの変更も画面へ自動的に反映されます。
ドラッグによるノードの配置はデータファイルに保存されません。

## 3. PowerShellから操作する

CLIは必ず `.\scripts\dagdo.ps1` 経由で使ってください。
ブラウザと同じローカルデータを操作でき、サーバーが停止中でも使えます。
`dagdo.ps1` はWindows PowerShell 5.1とPowerShell 7の両方に対応しています。
`bun run scripts/dagdo.ts <コマンド>` でも同じように操作できます。

### タスクを作る

```powershell
.\scripts\dagdo.ps1 add '画面の設計' --progress ready
```

実行結果に `a3f1b2` のような6桁のIDが表示されます。
以下の例の `a3f1b2` や `b2c3d4` は例示用です。実際に表示されたIDへ置き換えてください。
ほかのタスクと区別できる場合は、IDの先頭部分だけでも指定できます。

設計の完了後に行うタスクを追加する例です。

```powershell
.\scripts\dagdo.ps1 add '画面の実装' --after a3f1b2
```

`--after` は「指定したタスクの後」、`--before` は「指定したタスクの前」です。

### 確認・編集・完了のコマンド

| コマンド（`.\scripts\dagdo.ps1` の後に続ける） | 内容 |
| --- | --- |
| `next` | 未完了の前提タスクがなく、着手できるタスクを表示する。 |
| `next --limit 5` | 着手できるタスクを最大5件表示する。 |
| `list` | 未完了タスクを一覧表示する。 |
| `list --all` | 完了済みも含めて表示する。 |
| `list --done` | 完了済みだけ表示する。 |
| `status` | 全体の件数や、着手可能・待機中などの状況を表示する。 |
| `graph` | 依存関係を文字の図で表示する。 |
| `graph --mermaid` | Mermaid形式の図の定義を出力する。 |
| `show a3f1b2` | タスクの詳細、メモ、依存関係を表示する。 |
| `done a3f1b2` | タスクを完了にし、着手可能になった後続タスクを表示する。 |
| `reopen a3f1b2` | 完了を取り消す。 |
| `edit a3f1b2 --title '設計を見直す'` | タイトルを変更する。 |
| `edit a3f1b2 --progress in_progress` | 進捗を変更する。 |
| `edit a3f1b2 --note '完了条件をここに記録'` | メモを設定する。 |
| `edit a3f1b2 --clear-note` | メモを消す。 |
| `link a3f1b2 --before b2c3d4` | 既存タスクを A → B の順序でつなぐ。 |
| `unlink a3f1b2 b2c3d4` | 2つのタスク間の依存関係を外す。 |
| `rm a3f1b2 b2c3d4` | タスクと、それにつながる依存関係をまとめて削除する。ほかのタスクが依存している場合は `--force` が必要。 |
| `undo`、`redo` | ブラウザと共通の履歴で、元に戻す・やり直す。サーバーの起動中のみ使える。 |
| `projects` | プロジェクトを一覧表示する。 |
| `projects add '名前'` | プロジェクトを作成する。 |
| `projects rename <ID> '名前'` | プロジェクト名を変更する。 |
| `projects rm <ID>` | プロジェクトを削除する。タスクが残っている場合は `--force` が必要。 |
| `help` | コマンドの詳しい説明を表示する。 |

例：

```powershell
.\scripts\dagdo.ps1 next
.\scripts\dagdo.ps1 done a3f1b2
.\scripts\dagdo.ps1 graph
```

`done` は未完了の前提タスクがあると完了を拒否します。先に前提タスクを完了してください。

別のディレクトリから使う場合は、スクリプトを絶対パスで指定します。

```powershell
& 'C:\path\to\dagdo\app\scripts\dagdo.ps1' next
```

### AIエージェントから使う

AIエージェントは `skills/dagdo/SKILL.md` のスキルを使い、ブラウザと同じ操作を行えます。
タスクの追加・編集・完了・削除、依存関係、プロジェクト、Undo/Redo、Orcaワークスペースの操作が対象です。
ノードの配置やテーマなどの表示設定は対象外です。

スキルを有効にするには、メインのworktreeで次を一度だけ実行します。

```powershell
bun run scripts/install-skill.ts
```

`~/.agents/skills/dagdo` と `~/.claude/skills/dagdo` にリンクが作られます。
新しいエージェントセッションから使えます。

画像出力には `graph --png 'graph.png'`、SVG出力には `graph --png 'graph.svg'` を使えます。
画像出力には追加の描画用依存関係が必要で、Mermaid方式ではPlaywrightのブラウザも必要です。
通常の `graph` や `graph --mermaid` にはブラウザ描画環境は不要です。

## 4. 保存場所とバックアップ

現在の配置では、ファイルは次の場所に保存されます。

| 場所 | 内容 |
| --- | --- |
| `C:\path\to\dagdo\app` | アプリのソースコード。 |
| `C:\path\to\dagdo\data\data.json` | プロジェクト、タスク、依存関係のデータ。直接編集しないでください。 |
| `C:\path\to\dagdo\backups` | バックアップ。通常の世代は直近30件を保持します。 |
| `C:\path\to\dagdo\local\logs` | サーバーの動作ログ。 |

手動でバックアップを作るには、次を実行します。起動時にも自動で作成されます。

```powershell
.\scripts\backup.ps1
```

### バックアップから戻す

復元すると、そのバックアップ以降のタスク変更は戻ります。
先にUIと、AI・別ターミナルなどからのタスク更新をすべて停止してください。

1. `.\scripts\stop.ps1` を実行する。
2. `backups` 内から復元する世代のディレクトリを選ぶ。
3. 次のコマンドの `実際の世代名` を置き換えて実行する。

```powershell
.\scripts\restore.ps1 -Generation 'C:\path\to\dagdo\backups\実際の世代名' -WritesStopped
.\scripts\start.ps1
```

`-WritesStopped` は、ほかの更新処理を止めたことを示す指定です。
復元前のデータは `before-restore-*` に退避され、この退避コピーは自動削除されません。
同じディスク内のバックアップだけではディスク故障に備えられないため、必要に応じて外部へコピーしてください。

## 5. 困ったとき

| 状況 | 確認すること |
| --- | --- |
| ブラウザで開けない | `start.ps1` の結果を確認し、http://localhost:3737 を開く。 |
| ポートが使用中と表示される | 3737を使っているアプリを確認する。通常の起動は `start.ps1` に統一する。 |
| PowerShellでスクリプトがブロックされる | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1` のように実行する。Windows PowerShell 5.1とPowerShell 7に対応。CLIだけなら `bun run scripts/dagdo.ts` でも使える。 |
| Bunがないと表示される | `$env:USERPROFILE\.bun\bin\bun.exe` にBunがあるか確認する。 |
| UIのビルドがないと表示される | `.\scripts\check.ps1` を実行し、成功後に起動する。 |
| データ読み込みエラー | `data.json` を上書きせず、正常なバックアップから復元する。 |
| ロックのタイムアウト | 他の更新処理が動いていないか確認する。全処理の停止を確認するまではロックを削除しない。 |
| 詳細なエラーを調べたい | `local\logs` の新しいログを確認する。 |

このローカル構成では、クラウド同期とnpm経由の更新は無効です。
アプリを改造するときは、UIと更新処理の停止 → バックアップ → ソース変更 →
`check.ps1` → 再起動の順で進めてください。

ファイル構成や改造箇所は [リポジトリ構成ガイド（英語）](architecture.md)、
詳しい運用仕様は [Windows運用ガイド（英語）](windows-local.md) を参照してください。
